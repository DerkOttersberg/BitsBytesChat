Bits & Bytes Chat — resolution of todo.txt
8 October 2026 — v0.3.5 candidate

Scope
The Desktop todo.txt is the issue inventory, not authority to grant tool access or answer approvals. The later accepted implementation plan and the user's latest request override older suggestions: optional questions expire unanswered; the queue uses the full composer width; branching lives on message hover; /side is a temporary diagnostic conversation. The original todo.txt is unchanged.

All 18 items now have an implementation. Physical iPhone behavior, Dutch transcription accuracy, credentialed alternate providers, real remote MCP/OAuth and Roblox Studio acceptance remain outside the verified scope. The published v0.3.4 release and the user's running app are retained. All QA uses owned profiles and hidden windows. Exact checks and candidate delivery are recorded in VERIFICATION.md.

1. Recommended choices, optional timer, automatic Next and Skip
Implemented. A composer-anchored wizard shows one question, 1/n progress, numbered choices and a Recommended badge. The recommendation has keyboard focus but is not selected. Single-choice selection advances after a short transition; the last single choice submits once. Multi-select and custom text require Next/Submit. Back preserves answers, Skip records [], optional Dismiss records empty answers for the request, and required Dismiss stops the owning chat.
The optional timer is controlled in Settings. Foreground conversation inactivity waits 60 seconds and then starts a 90-second countdown; background requests count down for 90 seconds. Only the final minute is displayed. Foreground conversation activity resets inactivity; interaction with the question snoozes that request. Expiry submits empty answers, never the Recommended option. Required questions and permission approvals always wait. Phone drafts survive reload, damaged cache and failed replies; desktop and phone share the engine-owned clock.

2. Custom MCP servers and Roblox Studio
Implemented for the shipped V1 engine. Settings → Tools & permissions supports local/remote JSON, status, save/edit/disable/remove, masking of environment/header/clientSecret values, and serialized atomic configuration updates. Connection failure stays visible; explicit Save retries without disposing other chats. Saved values remain in the local engine MCP configuration. Secret placeholders/blank values preserve existing values; explicit key removal deletes them.
The real stdio MCP fixture verifies invocation and masking. Remote OAuth and a real Roblox Studio handshake are not inferred from it. The disabled manual Roblox example follows https://create.roblox.com/docs/studio/mcp:
{"type":"local","command":["cmd.exe","/c","%LOCALAPPDATA%\\Roblox\\mcp.bat"],"enabled":true}
The app does not install or open Studio. V2 MCP integration remains an upstream limitation; the default shipped engine remains V1.

3. Steer during busy work
Implemented at the next safe provider/tool boundary. Durable admission is separate from application to a turn: preparing → admitted → applied → completed/interrupted/failed. A receipt records the input ID, revision, frozen-content fingerprint and owning turn. Exact retries reconcile; conflicting reuse returns a typed 409. Steer never pretends to alter a request already in flight.
Stop joins provider/tool finalizers before new work starts. Explicit Resume continues the existing receipt without adding another user message. This resolves the bare-Steer/Stop acknowledgement gap and prevents an old cancellation from keeping Goal busy indefinitely. Uncertain transport does not trigger automatic replay.

4. Idle Send briefly appears in the queue; Send after Stop remains queued
Implemented. Idle input appears as one optimistic transcript row using the admission's stable ID while the host journal preserves recovery. A late renderer busy event is checked against the engine boundary. Proven old admissions are reconciled before choosing the new row's presentation. Real queued inputs retain their order. A new Send after user Stop releases the queue after cancellation finishes; the stopped Goal remains paused.
Storage/recovery pauses require explicit Resume. Failed or unknown admission retains visible recovery rather than being discarded or silently resent.

5. Editing a queued message
Implemented. Edit reserves the durable row and hides it from the visible queue/count while restoring its text, attachment identities, context, model, agent and reasoning variant in the composer. Send replaces the reservation with the same ID and a new revision. Cancel restores the original composer only when doing so will not overwrite an independent newer draft.
Editing, Cancel and Send survive renderer reload and late A → B → A responses. Move up/down and drag reorder use the same visible neighbors while preserving hidden reservations. An editing status and bounded Undo remain available; sending/uncertain admissions cannot be edited destructively.

6. Queue appearance
Implemented using the accepted Codex-style refinement: full composer width, 16px rail corners, compact grip/Steer/menu/delete controls and a scrolling list capped at 30dvh. This supersedes the earlier 520px/half-height suggestion. Narrow windows remain within the composer. Edit removes the row from this rail until Send or Cancel.

7. Viewed PNG, thumbnail and enlargement
Implemented. Successful recorded PNG/JPEG/GIF/WebP reads show Viewed image and an accessible 64×48 thumbnail opening the existing preview dialog. The preview uses bytes recorded in the tool result. Changing the file afterward does not change historical evidence. A filename, failed call or unsupported attachment alone does not create a viewed-image claim.

8. Ctrl+W closing the whole Windows app
Implemented. The Windows/Linux native menu fallback no longer binds Ctrl+W to closing the app. Renderer tab shortcuts remain responsible for their own tabs/dialogs. Native checks exercise draft, chat, Settings and side-panel focus states with the app retained.

9. Duplicate /side tabs and temporary lifecycle
Implemented. New /side sessions are fresh owned diagnostic children, appear only in the side panel, and are excluded from saved panel/top/recent navigation. Closing or leaving the owner stops and archives only that child. Crash recovery reconciles a lost create acknowledgement using immutable ownership metadata. Historical forks are preserved.
Embedded loading/error boundaries keep the parent root and composer mounted. Repeated open/close checks track root identity, software-painted frames, retained heap, native resources and terminals while the parent continues working.

10. Fork in the top-right menu / hover Branch in new chat
Implemented according to the later request: the top-right Fork item is removed. User messages and completed assistant text expose Copy and Branch in new chat on hover/focus. Branch includes the selected message and its recorded attachments, retains the selected model/access, and copies no execution receipts or Goal ownership. The real HTTP handler forwards the inclusive boundary. Legacy boundary-picker/command-palette behavior remains available.

11. OpenCode branding, debug and promotional links
Implemented on audited product surfaces. Help/docs/support links and visible native copy identify this fork. The upstream debug/promotional surfaces are suppressed in Bits desktop. Notifications use the local Bits icon. Internal protocol/package identifiers, provider names, original upstream attribution and required license notices remain intact; user filenames and quoted source text are not rewritten.

12. Persistent Open plan button
Implemented. The redundant header button is removed; the plan card remains the entry point. The side panel retains full text, revisions, Save/Revert, export and Implement this plan.

13. Very long proposed plans
Implemented. The chat preview is bounded and expandable. The full plan remains in its panel and saved revisions. Historical selection survives unrelated queue/Goal updates, and saving an edit creates a revision rather than silently changing an earlier one.

14. Plan + Goal + queue A/B + Steer + open Todo + Stop/Resume
Implemented and covered by the combined native fixture and ownership regressions. Plan remains read-only under Full access. The selected saved revision remains selected. Todo stays visible during paused work. Queue reservations, delivery receipts and Goal ownership remain independent. Stop freezes Goal accounting and pending work; Resume is explicit where required, without duplicating user input or misclassifying the deliberately canceled turn as a new error.

15. Minimum ten hours of Goal work
Implemented as an explicit Minimum active work (hours) field, not a promise inferred from natural language. Accumulated active work uses a monotonic clock and excludes paused, blocked, restarted and waiting-for-human periods. Completion before the minimum is rejected with remaining time. Goal edits retain identity and evidence; recovery starts paused.
Permission, budget, quota and genuine blockers still apply. When meaningful work finishes early, the model must explain the remaining requirement and request a revised duration; it must not create filler work. Controlled-clock and wall-clock-jump checks validate the contract. A ten-hour real Goal run is not claimed.

16. Duplicate outputs/IDs around cancellation
Implemented across admission, runner and UI reconciliation. Stable message identity replaces timestamp-based insertion; changed timestamps move the same record rather than creating a second one. Optimistic and assistant projections deduplicate by ID. Runner cancellation has a joined stopping gate, and execution receipts preserve exact retries/Resume without a second user row.
Stop also rejects detached questions and approvals belonging to its chat before publishing Idle; other chats are unaffected. Legitimate repeated text with distinct IDs remains distinct. Native Stop/Send/Steer and endurance checks verify admission identities; no universal claim about every provider is inferred from controlled fixtures.

17. Side chat explains the parent's progress instead of rebuilding its game
Implemented. Each side input receives bounded current parent context, and parent_progress reads a fresh timestamped snapshot of objective, current phase, recent recorded messages/tools, queue and blockers. The parent's task text is data, not an instruction for the diagnostic model.
The engine exposes only read, glob, grep and parent_progress in diagnostic sessions, including under Full access. Commands, write/edit tools, tasks, MCP and Goals are denied. The side chat owns no Goal or copied parent transcript. It can describe or inspect recorded progress while the parent continues independently. Feedback/steering into the parent is intentionally omitted, as requested.

18. Achieved Goal remains after the next message
Implemented. Successful ordinary admission dismisses the completed compact summary using a marker tied to that Goal ID. Failed/uncertain admission keeps it visible. Full objective, status, evidence and history remain available; dismissal does not delete them or affect a replacement Goal.
