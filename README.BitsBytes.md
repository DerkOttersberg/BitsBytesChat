## Recording, transcription and recovery

- Select your transcription model and microphone in **Settings → Audio**, then Save. Audio uses OpenRouter; local model, download and acceleration controls are removed. Import MP3, WAV, M4A, MP4, OGG, FLAC or WebM from **Recordings → Import audio**. Capture has no application duration cap, but transcription has provider limits. Keep the laptop awake; minimization is supported, Windows sleep suspends capture.
- **OpenRouter** uses the [dedicated transcription API](https://openrouter.ai/docs/guides/overview/multimodal/stt). Save your API key if one is not already connected, choose a **Transcription model**, optionally enter a language such as `nl`, and Save. The default is `elevenlabs/scribe-v2`; model discovery remains separate from chat. Leaving language blank enables automatic detection. Your chat provider and chat model stay independent. Audio API charges use OpenRouter credits, separately from your ChatGPT subscription. Component repair installs capture/preparation libraries without local speech-model downloads.
- **Separate speakers** requests Scribe v2's word timestamps and speaker labels. Recording still saves recoverable 30-second WAV chunks, but uploads one compressed mono MP3 after Finish so the provider can assign speakers over the whole recording. Independent chunk speaker IDs are never assumed to identify the same person. Scribe v2 and Scribe v2 Medical are supported; the toggle is disabled for other models. Uploads are bounded to 25 MB and processing has a bounded timeout. A large/slow recording receives an actionable error, with retained audio; turn the toggle off for ordinary chunked transcription or import shorter parts.
- **Transcript → Speaker names** renames speakers for that recording without another provider request. Names appear in text and future chat attachments. Existing immutable attachment revisions retain their original text. Anonymous speaker IDs do not automatically establish people's names or real identities. **Prepare speaker labels** explicitly reprocesses an older completed plain recording using the current Scribe settings.
- OpenRouter keys share the existing Windows-encrypted connection store. Credentials and audio are excluded from job events and logs. Missing/rejected keys, insufficient credits, rate limits and invalid responses have recoverable errors. Stop terminates the owned request process. A response lost after submission remains uncertain and is never automatically resubmitted; Resume is an explicit retry of unfinished chunks.
- Legacy local/Groq preferences migrate to OpenRouter for future recordings. Historical audio, jobs and transcripts remain readable; migration never uploads them. Reprocessing an old recording requires an explicit Resume or Prepare speaker labels action.
- Recordings and timestamps live in `%LOCALAPPDATA%\BitsBytesChat\recordings`. The app retains audio until you delete it. After an interruption, use **Resume transcription** in Recordings. Imported audio that was only partly decoded is resumed from its original file, which must still be available. Changing model, language or speaker separation deliberately rebuilds the transcript; retrying the same selection retains completed work. Each recording freezes these preferences independently of chat settings. A completed whole-recording diarization is not submitted twice on Resume or restart.
- **Transcript** displays the saved transcript. **Add to chat** attaches a compact transcript chip to your current draft. Older linked recordings retain **Open chat**. Cancel leaves saved audio in Recordings for recovery or deletion. Finish remains available while transcription runs in the background.

Audio is captured and retained locally, and uploaded to OpenRouter for transcription. With speaker separation enabled, that upload waits until Finish. Transcript text and chat attachments go to your selected chat provider. Enabling Windows control can also send tool results and screenshots to that provider. Phone microphone recordings and uploads use the same saved desktop Audio settings after upload.

Shared controls offer Open in app, Show in folder, Save copy and retry. Word and PowerPoint are required for their PDF previews; Excel recalculates workbook formulas for the sheet grid. Previews and errors do not block the next AI action.

## Computer tools and storage

Chat history, the model picker, file tools, terminal and agent engine remain available. Enabled skills use the local document helpers from chat; other agent actions use the chat’s access mode and configured tool restrictions. Sample tests disable model tool writes entirely. The local MCP tools also expose recording control, skill drafts/tests, template inspection and share testing. Windows-MCP 0.8.7 is optional: install it in Settings and enable **Windows application control**. Its tool calls use the chat’s Ask/Full access mode and can be cancelled. It uses a separate Python 3.14 runtime. Standard transcription uses Python 3.12.

This fork has its own app ID `nl.bitsbytes.chat`, protocol, icon and data/config locations. Upstream application updates are disabled.
