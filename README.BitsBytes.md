# Bits & Bytes Chat 0.3.4

Windows 11 desktop app built from OpenCode **v1.18.34**, upstream commit `aec0b9a6d8898f68f923aaf08b7306d931fd9d76`. The full source and runnable build are in this folder. The original upstream README and MIT license are retained.

## Start

Double-click **Start BitsBytesChat.cmd**. Both this launcher and **Start BitsBytes Mobile.cmd** open the same v0.3.4 application, which includes desktop chat and mobile access. There is one engine, data directory and set of features. The launcher reads the main package version and brings an existing current window forward. If an older desktop/mobile copy or a copy without a visible window is still running, it offers to close that copy; enter **Y** only when you are ready to interrupt its active work. It never closes a copy without this choice. Startup failures remain visible and logs are saved under `%LOCALAPPDATA%\BitsBytesChat\launcher`. Keep the accompanying `Start BitsBytesChat.ps1` beside the CMD file. The executable is `packages\desktop\dist\0.3.4\win-unpacked\BitsBytesChat.exe`. An optional installer is `packages\desktop\dist\0.3.4\BitsBytesChat-win-x64.exe`. This personal build is unsigned.

For the phone, open **Settings → Mobile access**, enable it and pair your phone while both devices are on the same network. The phone uses the computer's chats, model providers, tools and document helpers. Keep the computer running. See `MOBILE_ACCESS.md` for pairing, certificate and upload instructions. The earlier `dist\mobile` package is historical and is no longer targeted by either launcher.

If a Python environment points at an absent installation, startup repairs its home from the compatible pinned interpreter already installed in the app's runtime, preserving packages and a backup of the configuration. An unavailable audio worker shows a repair action in **Settings → Audio** while chat and mobile access continue to open. **Set up local components** now repairs existing environments as well as creating missing ones.

## Unreleased follow-up

Reliability changes on `chat-reliability` preserve queue controls during slow engine reads, recover temporary phone polling failures and damaged chat journals, and release closed browser resources. Stop also cancels prompt preparation and admission transport for that chat. An unsent request stays available for Resume; an admission already attempted is reconciled before retry. Stopping or failing a later preparation cannot erase uncertainty from an earlier attempt. Proven unsent failures retain their recovery error without repeatedly reading history. Busy queue polling avoids repeatedly downloading the full history, and phone status polling omits unused frozen prompt/draft copies. Phone updates retain unchanged message nodes and their selection/focus. CSV preview paging and file checks retain less temporary data; wide CSV previews now show the existing 100-column notice.

Large document inspections use saved numbered source parts, so the agent can read a complete source in bounded responses. Subsequent parts keep the inspected version even if its original file changes; a fresh inspection reads the latest file. Small Office/PDF/text inspections keep their structured results. These changes are verified source work; the published installer remains `v0.3.4`. See `VERIFICATION.md` for evidence and limits.

Spreadsheet preview pages also respect a byte budget. Long displayed values/formulas carry a shortening notice; saved files stay complete. Navigation follows actual page sizes on both devices.

Stop attempts to interrupt an active model request even when saving the queue pause fails. Both devices still show the storage error. Desktop notifications follow the displayed layout after navigation.

A background queue write failure pauses automatic work and shows its error without an unhandled rejection. Recovery retains the saved source and earlier admission history.

Damaged saved panel layouts retain usable neighboring tabs instead of preventing a chat from opening. The original layout remains available in a local recovery copy.

A temporary startup journal-write failure preserves saved work and opens chats paused. Unreadable journals remain protected. Development and isolated QA launches leave the installed Windows URL handler alone.

## New in 0.3.4

- Unconfirmed engine admission now becomes a visible recoverable request after its timeout, without an endless busy state or automatic duplicate. A late acknowledgement reconciles the original message.
- Shared terminal panels create one initial shell; intentional additional terminals keep distinct numbers. Retrying a historical document preview regenerates missing or damaged cache files without changing the current revision.
- Phone recording now has its own microphone in the composer. Pause/Resume, square Cancel and upward-arrow Finish are separate actions. Finish uploads in resumable chunks, transcribes on the laptop and attaches to the original chat draft; normal Send remains separate. Cancel retains audio on the phone without uploading. Saved browser chunks survive interruptions and can be recovered, downloaded or deleted from Audio uploads.
- Phone PDF code loads only when previewing a document. Compact attachment styling and notifications keep the draft unobstructed. A second tab cannot replace a live recording.
- Damaged optional saved-state files are preserved in recovery copies instead of preventing startup. Valid queues and artifacts survive an invalid neighboring entry. Concurrent document publication retains every revision, and nonexistent revisions produce an error instead of showing another version.
- Office previews reuse a validated content cache. Earlier Word/slides revisions can recover their own preview without replacing the current document. Failed attachment dispatch stops waiting and retains recoverable input, instead of leaving chat stuck.
- Windows source and upstream history are backed up in the private [DerkOttersberg/BitsBytesChat repository](https://github.com/DerkOttersberg/BitsBytesChat). QA scripts are included under `packages/desktop/scripts`; live AI checks explicitly opt in and default to GPT-5.6 Luna.

## Chat and document features

- While the assistant works: **Enter queues**, **Ctrl+Enter steers**, **Shift+Enter adds a line**. The upward arrow uses the selected default; the bent arrow uses the alternate action; the square stops and pauses pending work. Queue rows support Edit, reorder, delete, retry and a side chat. Settings → General changes the default follow-up behavior.
- **/plan** adds a removable lightbulb chip and enables read-only planning, including under Full access. Expand the proposed-plan card or open its tab. Edit, Save/Revert, export and select earlier revisions. **Implement this plan** submits the selected saved revision.
- **/goal** saves the next request as an ongoing objective. Its compact row opens an editable Goal tab with an optional token budget. Pause/Resume/Clear are available. Work continues after queued user input until the agent reports completion evidence, needs input, stops progressing or reaches a limit. Restart leaves unfinished work paused until Resume.
- Seven additional local skills cover Documents, PDFs, Spreadsheets, Presentations, Data analysis, Code/HTML and Skill creation. Templates are optional; the intake helper remains specialized. Install artifact helpers from **Settings → Tools & permissions**, or let the first artifact tool set them up automatically. These helpers use a separate Python environment, leaving transcription intact.
- Multiple generated files become clickable cards and named side-panel tabs. The first result of a response opens a closed panel; later results add unread tabs. Revisions refresh the same file and retain history. Word/slides/PDF use PDF previews, Excel uses a sheet grid, code uses the file viewer, and HTML has isolated Preview/Source. Corrections remain ordinary chat requests.

See [REFERENCE_ANALYSIS.md](REFERENCE_ANALYSIS.md) for the reference behavior, implementation choices and public sources, and [VERIFICATION.md](VERIFICATION.md) for measured checks and remaining limitations.

On first use:

1. Open **Settings → Audio**. If needed, install local components and download Parakeet. These are one-time downloads. Select the microphone, transcription provider and acceleration here.
2. Use **Settings → Providers** for ChatGPT plan, OpenAI API, OpenRouter, Google, Anthropic or any provider supported by the retained engine. ChatGPT plan uses this app's registered sign-in; it is separate from OpenAI API billing. Existing connections and choices are preserved. **Models** manages the native model picker.
3. Set each skill’s template and output folder in **Skills**. There is no Documents & storage settings page. Existing saved destinations continue to work. **Settings → Tools & permissions** enables AI browser tools and optional Windows application control. Every settings entry opens this same dialog.

Daily: select `/bits-en-bytes-intake` from slash suggestions to attach the intake skill, type your request, then record with the **microphone in the composer**. During recording, **square cancels**, the middle control pauses/resumes, and **upward arrow finishes and attaches**. The normal **Send** button remains separate. The recording attaches to the draft where capture started, even if you change chats. Cancel retains recoverable audio under Recordings.

Transcripts and selected skills appear as compact, removable chips. Click one to read its contents in the right panel. Sent messages also show chips; the model still receives the source context. A transcript is frozen at attachment time so retries and branches use the same source. Sources above 32,000 characters use numbered 16,000-character parts; document tools require every attached part to be read. The model is instructed to extract facts from every part. No transcript text is silently cut off. Multiple skills are supported, with each saved revision and its resources. A skill-only message uses its saved default prompt. Ordinary slash commands retain their existing behavior.

Use the original OpenCode side-panel icon **beside the context-window indicator in the main chat header** to open or collapse the panel. The toggle stays available when there are no panel tabs. An empty panel starts closed; opening it exposes the **+ beside the side-panel tabs** for **Side chat, Browser, Terminal, Code review, Open file** (click or right-click). There is no side-panel + in the top bar. Tabs share one resizable, collapsible panel, and closing the last tab leaves the empty panel available. Enter **/side** or choose **Side chat** to branch through the last completed turn. The side chat looks empty initially while retaining the complete inherited context for the model. Its new messages remain visible after reopening. It initially copies the model and access mode, then keeps independent messages, draft, model and cancellation. Code review is available from the panel menu. Closing a side-chat tab retains its conversation in history.

The browser uses an isolated Electron WebContentsView and an app-specific persistent profile. Its toolbar supports addresses, back/forward and reload/stop. Enabled AI browser tools can inspect, navigate, screenshot, click, type and scroll. Web pages have no Node access or privileged app bridge. Browser actions follow the originating chat's access mode.

At the bottom left of each composer, use the styled menu to choose **Ask for approval** or **Full access**. Full access has a muted orange exclamation indicator. Model and reasoning controls sit on the right. New chats start in Ask. Ask permits reading and asks before changes, commands and browser/computer actions. Full access allows enabled tools. The engine checks the mode for each action, including background execution; switching back to Ask removes automatic approval for subsequent actions. Explicit disabled/denied tools remain unavailable. Cancellation stays available.

ChatGPT subscription access is the documented public Sign in with ChatGPT flow with this app's own dynamic registration. It requires an eligible account and granted permission. The app does not import your ChatGPT history or account context. OpenRouter and Groq require their own keys. Reaching subscription limits never switches you to a paid provider automatically.

## Recording, transcription and recovery

- Select **Audio transcription** and your microphone in **Settings → Audio**, then Save. Parakeet, Whisper Turbo and Groq are available. Import MP3, WAV, M4A, MP4, OGG, FLAC or WebM from **Recordings → Import audio**. There is no application duration cap. Keep the laptop awake; minimization is supported, Windows sleep suspends capture.
- **Local Parakeet** is the default: multilingual TDT 0.6B v3, including Dutch, through ONNX-ASR. It uses CPU without requiring an RTX card. Automatic mode uses compatible installed CUDA providers where available and retries on CPU if acceleration fails.
- **Local Whisper Turbo** uses faster-whisper large-v3-turbo with Dutch selected. Its model is a separate one-time download.
- **Online Groq Whisper** clearly marks uploads. It sends 30-second mono WAV chunks, below the 25 MB per-request limit. Groq's published free-tier allowance currently lists 2 audio hours per hour and 8 per day; quotas can change. Quota errors are visible and completed chunks remain available.
- Recordings and per-chunk timestamps live in `%LOCALAPPDATA%\BitsBytesChat\recordings`. The app retains audio until you delete it. After an interruption, use **Resume transcription** in Recordings. Imported audio that was only partly decoded is resumed from its original file, which must still be available. Changing engines deliberately rebuilds the transcript.
- **Transcript** displays the saved transcript. **Add to chat** attaches a compact transcript chip to your current draft. Older linked recordings retain **Open chat**. Cancel leaves saved audio in Recordings for recovery or deletion. Finish remains available while transcription runs in the background.

Audio remains on the laptop with local transcription. Transcript text and chat attachments go to your selected AI provider. Enabling Windows control can also send tool results and screenshots to that provider. Groq transcription uploads audio only when explicitly selected.

## Skills and documents

The bundled intake package includes the original Dutch instructions, references and Python helper. The installed original Codex skill is unchanged. The helper fills and verifies 13 supported fields, retains the Word template's formatting, preserves text identifiers and leaves unknown values blank. Instructions tell the model to distinguish the participant, employee, accompanying person and formal contact person and to treat transcripts and documents as source data.

**Skills** supports AI drafting from a task description and optional template, editing instructions/default prompts/destinations, full folder import/export, resources, enabled/draft state and complete package versions. Chosen templates are copied into the package. **Open package resources** opens the skill folder so you can edit references and scripts. Saving snapshots the entire package. Imported skills start disabled. **Test in local folder** runs the selected model with tool writes disabled and creates its structured output in `%LOCALAPPDATA%\BitsBytesChat\tests`; it never uses the live destination. Intake tests use the specialized template helper. Other tests support common Word, spreadsheet, slides, PDF and HTML specs; they do not execute arbitrary custom scripts. Advanced skills use the artifact script tool in a normal chat with its access permissions.

Intake filenames are `Intakegesprek voornaam achternaam.docx`, with `(2)`, `(3)` etc. for collisions. Each document job snapshots and validates its template when you request the document. Missing templates stop document creation with a recovery message. A damaged snapshot is rejected; fix the configured template and click **Refresh template snapshot** in Recordings. If the server save fails, the verified local file stays in `%LOCALAPPDATA%\BitsBytesChat\documents`. Use **Retry saving to server** when the share returns. Document write intentions and verified payloads are journalled before saving, so a crash after writing can recover the same artifact. A retry while offline keeps the same local file. Partial corrections preserve other fields, and repeating an identical correction returns its existing revision.

Verified files are a persistent collection associated with their originating chat and response. The first result of a response opens the panel, including when it is collapsed; later results add unread tabs without repeatedly changing focus. Revisions refresh the existing tab. Earlier response cards open their original saved revision, with the latest version available in the preview menu. During export the previous preview stays visible with a small status indicator. Export completion does not steal focus if you switch away. Restoring saved artifacts does not select them over another saved tab. Scripts can publish supported files with `publish_artifact`. Office exports run in a separate process, independent of transcription, queued and cached by content. PDF.js provides zoom, Fit width and page navigation. Shared controls offer Open in app, Show in folder, Save copy and retry. Word and PowerPoint are required for their PDF previews; Excel recalculates workbook formulas for the sheet grid. Previews and errors do not block the next AI action.

## Computer tools and storage

OpenCode's chat history, model picker, file tools, terminal and agent engine remain available. Enabled skills use the local document helpers from chat; other agent actions use the chat’s access mode and configured tool restrictions. Sample tests disable model tool writes entirely. The local MCP tools also expose recording control, skill drafts/tests, template inspection and share testing. Windows-MCP 0.8.7 is optional: install it in Settings and enable **Windows application control**. Its tool calls use the chat’s Ask/Full access mode and can be cancelled. It uses a separate Python 3.14 runtime. Standard transcription uses Python 3.12.

This fork has its own app ID `nl.bitsbytes.chat`, protocol, icon and data/config locations. Upstream application updates are disabled. Credentials use Electron's Windows encryption and are never written into the project or the OpenCode provider config. Only ephemeral loopback bridge tokens appear there. Both bridge servers bind to `127.0.0.1` and require a random credential.

## Build and verification

Run **Build Windows.ps1** to install dependencies, type-check, build the embedded engine and package Windows. It uses Bun 1.3.14. The downloaded Bun is retained in `.tools` for this checkout. The engine retains upstream version 1.18.34 for compatibility with published plugin dependencies; this app has version 0.3.4. Mobile access is built and packaged with this same application; a separate mobile package is no longer produced.

Relevant source: `packages/desktop/src/main/bitsbytes*.ts`, `src/renderer/bitsbytes`, `src/bitsbytes`, and `resources/bitsbytes`. The Python recording worker is a local JSON-lines daemon; Word preview exports are separate processes; jobs have durable identifiers, manifests, progress, errors and artifact references. Local agent capabilities are exposed through its authenticated stdio MCP adapter.

See **VERIFICATION.md** for measured results and remaining checks. Earlier 0.2 checks passed live ChatGPT refresh/inference and tool permissions; the new 0.3 interaction checks use a local test provider. Other live provider checks require corresponding keys. The latest successful account-specific catalog currently omits GPT-6.1 Sol; the app does not invent availability. The model picker explains that availability and offers **Refresh ChatGPT models**. A failed model refresh keeps a labelled cached list. Dutch accuracy testing was skipped at your request; no accuracy percentage is claimed.

If launched from a Microsoft Store application such as Codex, Windows may place local data in that application's virtualized LocalCache. Launching normally from Explorer can therefore require the one-time component setup and sign-in again. The app uses the launch environment's Windows local data location; recordings and credentials are never stored in this OneDrive project. Component setup runs in a hidden process; its progress is shown as Working until it completes.
